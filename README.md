# FinanceTracker

Консольное приложение на Java 21 для учёта личных финансов: несколько пользователей,
личные кошельки, доходы и расходы, категории и бюджеты, статистика, оповещения,
переводы между пользователями, экспорт и импорт JSON/CSV.

## Запуск

Нужен JDK 21+. Maven устанавливать не нужно — в проекте есть Maven Wrapper.
Зависимости (Jackson, JUnit 5) скачиваются автоматически.

```bash
./mvnw test                    # тесты
./mvnw verify                  # тесты + Checkstyle + покрытие
./mvnw -q compile exec:java    # запуск
```

В Windows PowerShell используйте `.\mvnw.cmd`. Если русский текст в терминале
отображается некорректно, запустите класс `Main` из IntelliJ IDEA.

Данные создаются автоматически: `data/users.json` — пользователи,
`data/wallets/<логин>.json` — категории, бюджеты и операции. Папка `data/` в Git не попадает.

## Быстрый старт

```text
register                        # затем ввести логин anna и пароль secret1
add-category Еда
add-category Зарплата
set-budget Еда 4000
add-income Зарплата 60000
add-expense Еда 300 "обед"
report
exit
```

`report` покажет общий доход, расходы по категориям, остаток бюджета и оповещения.
Для условий задания вывод выглядит так:

```text
Общий доход: 63,000.00
Общие расходы: 8,300.00
Еда: бюджет 4,000.00, остаток 3,200.00
```

Правила ввода:

- название из нескольких слов — в кавычках: `add-category "Коммунальные услуги"`;
- сумма — положительное число (`300` или `300.50`);
- дата — `ГГГГ-ММ-ДД`, будущие даты запрещены; по умолчанию сегодня;
- категории и логины не зависят от регистра.

## Команды

Справка по всем командам: `help`; по одной: `help <команда>`.
До входа доступны `help`, `register`, `login` и `exit`.

| Группа | Команды |
|---|---|
| Вход | `register`, `login`, `logout`, `exit` |
| Категории | `categories`, `add-category <название>`, `rename-category <старое> <новое>`, `remove-category <название>` |
| Бюджеты | `set-budget <категория> <лимит>`, `remove-budget <категория>` |
| Операции | `add-income <категория> <сумма> [описание] [--date дата]`, `add-expense ...`, `transfer <логин> <сумма> [комментарий] [--date дата]` |
| Отчёты | `report [--categories "Еда,Такси"] [--from дата] [--to дата] [--out файл]`, `history` с теми же опциями |
| Файлы | `export <файл.json\|файл.csv>`, `import <файл.json\|файл.csv>` |

Примеры:

```text
add-expense "Коммунальные услуги" 3000 "за ноябрь" --date 2026-11-10
report --categories "Еда,Такси" --from 2026-11-01 --to 2026-11-30
history --from 2026-11-01 --out history.txt
```

`--out` сохраняет отчёт или историю в файл; существующий файл не перезаписывается.

## Оповещения

- превышен бюджет категории;
- израсходовано 80% лимита и больше;
- расходы превысили доходы;
- баланс равен нулю.

После добавления операции показываются оповещения по её категории, в `report` — по всему кошельку.

## Переводы

`transfer` создаёт расход у отправителя и доход у получателя в категории «Перевод».
Получатель должен быть зарегистрирован, но может быть не в сети. Перевод самому себе
запрещён; сумма не может превышать баланс отправителя.

## Экспорт и импорт

- `.json` — полный снимок кошелька (категории, бюджеты, операции);
- `.csv` — только операции; формат определяется по расширению файла;
- существующий файл при экспорте не перезаписывается;
- импорт добавляет данные, создаёт недостающие категории и сначала проверяет файл целиком;
- повторный импорт создаст дубликаты операций.

CSV должен начинаться с заголовка (UTF-8, разделитель — запятая):

```csv
date,type,category,amount,description,counterparty
2026-11-10,EXPENSE,Еда,300.00,обед,
```

## Архитектура

Три слоя, зависимости идут в одну сторону: `cli` → `core` ← `infra`.

| Слой | Содержимое |
|---|---|
| `core` | модель, бизнес-правила, статистика, оповещения, интерфейсы `UserRepository`, `WalletRepository`, `WalletFormat` |
| `infra` | JSON-хранилище, PBKDF2, форматы CSV/JSON |
| `cli` | разбор команд, цикл ввода, команды, таблицы и форматирование |

`Application` собирает хранилища, сервисы и команды, `Main` — точка входа.

Ключевые решения:

- деньги хранятся в `BigDecimal` с двумя знаками;
- модель неизменяемая, баланс вычисляется из операций;
- каждая команда — отдельный класс, `help` строится по реестру команд;
- пароли хранятся как PBKDF2-хеш со случайной солью;
- кошелёк сохраняется после изменений и при выходе, загружается при `login`;
- запись атомарная, повреждённый файл не перезаписывается.

## Тесты

```bash
./mvnw verify
```

- 60 тестов: 10 интеграционных сценариев (`ApplicationTest`) и 50 модульных проверок модели;
- покрытие строк — 75,0% (ветвей — 61,4%), порог JaCoCo — 50%;
- Checkstyle проверяется на фазе `verify`, CI — в `.github/workflows/ci.yml`;
- отчёт о покрытии: `target/site/jacoco/index.html`.


## Ограничения

- Пароль виден при вводе: скрытый ввод в консолях IDEA и Git Bash ненадёжен.
- Перевод записывает два файла; при сбое второй записи данные могут временно разойтись.
- Один экземпляр приложения на папку `data/`.
